  3 аппаратных теста и публичные тесты по умолчанию пропущены.
- `cargo test --locked --test worker_network -- --ignored --nocapture --test-threads=1`:
  оба публичных сценария прошли за 54,50 с (чат, Opus, кик, четыре повторных входа).
- `cargo build --release --locked` и упаковка прошли; оба публичных сценария
  повторены на `target/release/thodtalk.exe`: 2/2, 52,93 с. ZIP проверен упаковщиком
  на структуру, manifest, безопасные пути, размер и SHA-256.
- Локальный тест трёх клиентов дополнен проверкой прикладного RTT гостям и владельцу.
- Проверены ограничение журнала 250 событиями и удаление управляющих символов.
- В debug-приложении с временным профилем визуально проверены отдельное окно,
  цветные карточки, настройка в разделе «Основное», выключение и повторное открытие.
- Реальная диагностика показала HTTPS-ответ всех четырёх штатных relay;
  азиатский relay подтвердил контрольный QUIC-обмен (712 мс); на европейском
  и восточном американском relay наблюдались ошибки обмена. Это результат конкретной сети в момент проверки,
  не утверждение о глобальной доступности relay.

Сетевые тесты — отдельные процессы на одном компьютере с публичным начальным
маршрутом; они не заменяют тест двух провайдеров. Акустическая задержка,
физические аудиоустройства, длительный разговор и отключение роутера не проверялись.
Настройка сохраняется штатной кнопкой «Сохранить»; синтетический профиль можно
создать через `cargo run --example seed-test -- <пустой-каталог> --diagnostics`.

# Исправление подключения 0.3.10 — 17 ноября 2026

На текущем компьютере воспроизведён исходный `deadline has elapsed`.
Отдельная проверка штатных публичных relay показала: азиатский маршрут передаёт
данные; европейский и оба американских зависают после начала QUIC-соединения.
Это наблюдение данной сети в момент проверки, а не утверждение о глобальном сбое.

Исправления:
- сервер выбирает relay по реальному двустороннему QUIC-обмену через интернет;
- код TT4 содержит relay, но не локальные IP, и не выдаётся при неготовой сети;
- удалены LAN-discovery, тестовые переменные маршрутизации и неиспользуемый probe;
- повторный вход создаёт новое состояние MLS с прежним ключом личности;
- отключение отправляет Shutdown, ограничивает ожидание и завершает только свой worker;
- при потере stdin worker завершается; проигравшие маршруты отменяются;
- сервер освобождает место участника после 15 секунд без его пакетов;
  гости отправляют контрольный пакет каждые 3 секунды.

Проверки выполняются с временными профилями. Реальные данные пользователя не меняются.
Публичные тесты используют отдельные процессы на одном ПК: начальный маршрут
идёт через внешние relay, без LAN-discovery и локальных адресов в приглашении.
После соединения iroh может перейти на обнаруженный прямой путь. Проверка
готовности relay отдельно запрещает IP-транспорт и выполняет обмен через интернет. Они не заменяют проверку
между двумя разными провайдерами и перезагрузку физического компьютера.

Команды:
```
cargo test --locked
cargo test --locked --test worker_network -- --ignored --nocapture --test-threads=1
cargo test --locked --test worker -- --ignored --nocapture
```

`worker_network` проверяет текст, Opus-пакеты, кик и четыре повторных входа
с одним сохранённым ключом (обычный Shutdown и аварийное завершение процесса).
`worker` отдельно проверяет завершение активного процесса по Shutdown и потере stdin.
Результаты исходников 0.3.10: `cargo test --locked` — 26 модульных тестов и
1 обычный worker-тест прошли; тест активного завершения запущен отдельно и прошёл.
Оба публичных сценария worker_network прошли за 55,17 с; подключение двух гостей
заняло 2,84 с. Тесты захвата экрана и реальных аудиоустройств здесь не запускались.
Оптимизированный пакет дополнительно проверяется теми же публичными сценариями.

# Отчёт проверки сборки 0.2.1

Проверки выполнены 13 ноября 2026 на Windows x64. Все автоматические сценарии
используют отдельные временные профили; рабочие пользовательские данные не менялись.

## Проверено

- Групповое MLS-шифрование, отклонение повреждений, повторов и постороннего
  получателя; удалённый участник не расшифровывает новую эпоху.
- Реальные TCP/QUIC-соединения, проверка секрета приглашения и закрытого входа.
- Три локальных клиента: текст, Opus-аудиокадр внутри MLS, кик, сохранение истории,
  неизменность общего кода и новый код при перезапуске.
- Публичный маршрут iroh с отключённым LAN discovery: библиотечный тест трёх
  клиентов прошёл за 91,26 с; тест трёх отдельных процессов готового EXE — за
  81,38 с. Проверены текст, зашифрованный аудиокадр, кик и работа оставшихся
  участников при закрытом входе. Это три процесса на одном компьютере,
  а не три разных провайдера. Потребовались повторные подключения.
- Профиль и история DPAPI, атомарное сохранение, ошибки повреждения файлов.
- Worker отклоняет неправильное приглашение и завершается после закрытия stdin.
- Устройства микрофона и вывода на этом компьютере открылись без ошибок;
  тест длился 300 мс, передача была выключена, запись не создавалась.
- В окне вручную проверены запуск сервера, отправка сообщения клавиатурой и
  завершение процесса при закрытии окна. Новый тёмный дизайн визуально проверен.
- EXE использует только системные DLL Windows; Opus и Rust runtime включены.

Окончательный результат сборки и упаковки фиксируется в
`dist/0.2.1/verification.txt`. Файл не содержит приглашений, профилей или ключей.

## Проверить вместе с друзьями

1. На двух-трёх компьютерах в разных сетях войти по одному коду. Затем назначить
   другого друга хостом и повторить. При необходимости обработать штатный запрос
   брандмауэра вручную; на первом подключении дождаться повторных попыток.
2. В наушниках поговорить 10–15 минут: микрофон, «Без звука», F8, переключение
   каналов и устройств. Оценить задержку, прерывания и нагрузку. Акустическое
   качество на нескольких физических устройствах автоматически не проверялось.
3. Изменить имя/фото, перезапустить приложение и проверить историю. Кикнуть
   участника, закрыть вход и убедиться, что остальные продолжают общение.

## Воспроизводимость

`scripts/check.ps1` — обычные тесты и сборка. Дополнительные сетевые проверки:

```
cargo test --release --test internet -- --ignored --nocapture
cargo test --release --test worker_network -- --ignored --nocapture
```

В 0.3.10 LAN-discovery удалён; тестовый переключатель PUBLIC_ONLY больше не используется.
Диагностический `THODTALK_TEST_TRACE` задаёт путь журнала сетевого теста.
Такой журнал может содержать сетевые адреса; в пакет он не включается.

Непроверенные условия: разные провайдеры и CGNAT, длительные многолюдные
разговоры, Bluetooth-гарнитуры всех моделей, приостановка Windows и смена сети
во время разговора. Светлая тема и минимальный размер окна ещё требуют
пользовательской оценки. Эти сценарии не выдаются за прошедшие тесты.
